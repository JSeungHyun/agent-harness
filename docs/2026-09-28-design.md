# agent-harness 설계

| | |
|---|---|
| 작성 | 2026-09-28 |
| 상태 | ⛔ **미검증 설계안.** 1호 적용(ICFR) 전까지 아무것도 증명되지 않았다 |
| 1호 대상 | `~/Projects/ICFR/icfr-backend` |

## 0. 승인된 결정

| | 결정 | 기각된 대안 |
|---|---|---|
| 운영 모드 | **자율 루프**(`AGENTS.md §1`)가 기본. 스킬은 호출형 | superpowers 의 승인 게이트를 기본으로 |
| 보안 검사 | 상시 훅 제거 → **태스크 경계 게이트** | 상시 훅 전부 유지 |
| 이름 | `agent-harness` | `evidence-gate` · `solo-loop` |
| 1차 범위 | **아티클 6역할 전부** | 검증된 것만 + LESSONS |
| 순서 | 레포 먼저 → ICFR 적용 → 개발 재개 | 정리 → 개발 → 레포 |

⛔ **1차 범위는 작성자의 권고와 다르다.** 권고는 「증명된 것만」이었고 사용자가 6역할 전부를 택했다.
그래서 **버리는 대신 딱지를 붙인다** — 모든 산출물에 `검증됨` / `설계안` 을 명시하고, 설계안은
1호 적용에서 실제로 값을 냈을 때만 `검증됨` 으로 바꾼다. 딱지 없는 항목은 이 레포에 들어오지 않는다.

## 1. 자리 — 이미 있는 두 레포와의 분담

| 레포 | 답하는 질문 | 근거 |
|---|---|---|
| `context-graph` | **무엇을 아는가** — 현업 용어 → 코드 식별자, 함정 | APMS 기록 168건 |
| `agent-init-template` | **누가 어떤 순서로 도는가** — 중계기 + plan/dev/review, 잠금, 관문 | 실주행 15건 파손 후의 규칙 |
| **`agent-harness`** | **혼자 도는 세션이 멈추지 않으면서 어떻게 증명하고 무엇을 남기는가** | ICFR 에서 손으로 만들어짐 |

⛔ **`agent-init-template` 의 부분집합이 아니다.** 저쪽은 다중 에이전트 파이프라인이고, 이쪽은
중계기도 서브에이전트도 없는 **단일 세션 자율 루프**다. ICFR 이 그 모델을 택했고 그대로 돌고 있다.

⚠️ **세 레포를 한 프로젝트에 동시에 얹는 것은 검증되지 않았다.** 1호는 `agent-harness` 단독으로 간다.

## 2. ⛔ 전제 정정 — `AGENTS.md` 는 이제 자동 로드된다

`context-graph/README.md` 와 `SETUP.md §1-b` 는 *"Claude Code 는 `AGENTS.md` 를 자동 로드하지
않는다 … 이 다리를 놓지 않으면 저장소 전체가 무용지물"* 이라고 못박았다. **실측(2.1.259, 2026-09-04)**

**2026-09-28 재실측 — 뒤집혔다.**

```
버전   2.1.283
대상   icfr-backend (CLAUDE.md 없음)
방법   claude -p --model haiku, 도구 전면 금지

양성   "이탈 조건 두 가지는?" → "1. 주간 토큰 60% 도달  2. 계획된 구현 전체 완료"   ← AGENTS.md §2 원문
음성   "야간 배포 금지 시간대는?" → "모름"                                          ← 환각 아님
```

⇒ **`CLAUDE.md` 다리는 더 이상 필요 없다.** 이 레포의 `SETUP.md` 는 다리를 놓지 않는다.
⇒ `context-graph` 의 해당 절과 `icms-control/CLAUDE.md`(`AGENTS.md` 전문 복사본 + "동기화하라" 규칙)는
   수정 대상이다. 이 설계의 범위 밖이지만 기록해 둔다.

⚠️ **남은 의문 하나** — `/clear` 직후 세션에는 `AGENTS.md` 가 안 들어온 관측이 1회 있다. 새 세션에서는
들어오는 것이 확인됐으므로 `/clear` 경로만의 문제로 보이나 **재현 미실시**다. `SETUP.md §검증` 이 이것을 본다.

## 3. 정직한 값 — 기존 수단으로 되는 것은 뺀다

| 차원 | 이미 되나 | 판정 |
|---|---|---|
| 테스트 통과 여부 | ✅ CI · gradle | ⛔ 고유값 아님 |
| 진행 상태 나열 | ✅ 계획서 체크박스 | ⛔ 고유값 아님 |
| 무엇이 언제 바뀌었나 | ✅ git | ⛔ 고유값 아님 |
| 현업 용어 → 코드 | ✅ `context-graph` | ⛔ 여기서 안 다룬다 |
| **체크박스가 거짓말하는지 판정** | ❌ 사람이 쓴 주장일 뿐 | ⭐ 고유값 |
| **묻지 않고 진행한 가정의 적립** | ❌ 어디에도 없다 | ⭐ 고유값 |
| **반복 실패 → 규약 승격** | ❌ | ⭐ 고유값 |
| **"완료"의 증거 강제** | ❌ `BUILD SUCCESSFUL` 은 테스트 0개여도 성공한다 | ⭐ 고유값 |

⛔ **이 표가 흐려지면 이 레포는 git 과 CI 의 열등한 사본이다.** 도구를 추가할 때마다 이 표에 줄을 넣고,
「이미 되나」가 ✅ 면 넣지 않는다.

## 4. 6역할 설계

### ① 요청 → 계약

| | |
|---|---|
| 산출물 | `templates/plan.skeleton.md` · `tools/task-extract.mjs` |
| ICFR 근거 | 계획서의 Task 표가 이미 「완료 기준」 컬럼을 가진다 (Task 7: *"`/api/controls`, 타 tenant 404"*) |
| 검증 상태 | 개념 **검증됨** · JSON 추출 **설계안** |

`done_when` 은 **값이 아니라 명령**으로 적는다.

```
- [ ] Task 7 — 통제 목록 + tenant 격리
      done_when: ./gradlew test --tests '*ControlControllerTest' → failures=0
      escalate_when: 마이그레이션 되돌리기가 필요해진다
```

⛔ **저장소를 둘로 만들지 않는다.** 아티클은 `contracts/task.schema.json` 을 별도로 두지만, 계획서와
task.json 이 둘 다 있으면 반드시 어긋난다. ⇒ **계획서가 정본이고 스키마는 검사기용 추출본**이다.
`task-extract.mjs` 가 계획서에서 뽑고, 사람은 계획서만 고친다.

### ② 컨텍스트 컴파일

| | |
|---|---|
| 산출물 | `templates/AGENTS.snippet.md` · `tools/context-audit.mjs` |
| ICFR 근거 | `AGENTS.md` 10절이 지도 역할을 이미 한다 |
| 검증 상태 | 지도 형식 **검증됨** · 검사기 **설계안** |

`context-audit.mjs` 가 재는 것 — **AGENTS.md 가 지도인가 백과사전인가**:

- 줄 수 · 절 수 (임계 초과 시 경고)
- **절 번호 중복·결번** ⭐ ICFR 의 「5가 두 번, 6이 없음」이 여기서 잡힌다
- 깨진 참조 — 본문이 가리키는 파일·명령이 실재하는가
- 자동 로드 실측 — `claude -p` 도구 금지 양성/음성 대조 (§2 의 방법)

⛔ **자동 로드되는 층을 늘리지 않는다.** 이 레포의 도구는 전부 **호출해야 도는 것**이고, `AGENTS.md`
외에 세션마다 주입되는 파일을 새로 만들지 않는다.

### ③ 모델–도구 게이트웨이

| | |
|---|---|
| 산출물 | `policy/permissions.yaml` · `tools/policy-apply.mjs` · `tools/policy-diff.mjs` · `tools/surface-report.mjs` |
| ICFR 근거 | user/project 두 스코프에 allow·deny·ask 가 흩어져 있고 backend·web 이 제각각 |
| 검증 상태 | 정책 내용 **검증됨** · yaml 단일 원천 **설계안** · `surface-report` **설계안** |

사람이 읽는 정책 한 곳에서 `settings.json` 을 생성한다. `policy-diff` 가 현재 설정과의 괴리를 본다.

`surface-report.mjs` — **노출 도구 수를 센다.** 아티클의 안티패턴 *"모든 도구를 에이전트에 노출"* 을
수치로 만든다. ICFR 실측(2026-09-28): playwright 27 · Google Drive 11 · 그 밖 커넥터 다수가 상시 노출.

⚠️ **claude.ai 계정 커넥터는 이 도구가 끄지 못한다.** 웹 설정이다. 보고서에 「레포 밖 조치 필요」로 낸다.

### ④ 메모리를 영구 상태로

| 유형 | 대상에서의 위치 | ICFR 근거 | 검증 상태 |
|---|---|---|---|
| FACTS | `AGENTS.md` | 있음 | **검증됨** |
| STATE | 대상이 이미 쓰는 곳 | ⭐ `docs/reference-audit.md` + `./gradlew referenceAudit` | **검증됨** |
| DECISIONS | 대상이 이미 쓰는 곳 | ⭐ `Need-Check.md` — 4건 열림 · 5건 해소 | **검증됨** |
| LESSONS | 대상이 정하는 곳 | **없음** | ⭐ **신규** |

⛔ **파일 위치를 강제하지 않는다.** 이 레포의 `templates/state/` 는 **틀**이고, 대상은 이미 쓰는 경로를
그대로 둔다 — ICFR 은 `docs/reference-audit.md` 와 루트 `Need-Check.md` 다. `SETUP.md` 가 대상의
실제 경로를 조사해 `harness.json` 한 곳에 적고, 도구들은 그 파일만 읽는다. 옮기면 기존 참조가 깨지고,
깨진 참조는 `AGENTS.md` 가 이미 여러 곳에서 가리키고 있어 비용이 크다.

STATE 의 형태는 `reference-audit.md` 를 그대로 따른다 — **행마다 대상 + 상태 + 해시**, 해시가 달라지면
그 행이 자동으로 재작업 대상으로 돌아온다. `tools/state-check.mjs` 가 해시 불일치·경로 소멸을 잡는다.

⛔ **`분석완료` 를 사람이 쓰는 것이 이 구조의 약한 고리다.** `AGENTS.md` 가 *"읽은 척하지 않는다"* 로
막고 있으나 기계는 판정하지 못한다. `context-graph` 가 같은 자리에서 같은 한계를 기록했다.

LESSONS — ⭐ **이 레포가 새로 만드는 유일한 것.**

```
tools/lesson-append.mjs   실패 1건 기록 (증상 · 근본원인 · 분류 · 재현 케이스 경로)
tools/lesson-promote.mjs  같은 분류가 N회 → 규약 승격 후보로 올린다
```

분류는 아티클을 따른다: `누락된 컨텍스트` · `잘못된 도구` · `미흡한 권한` · `검증 부족`.

ICFR 에서 승격이 이미 손으로 3번 일어났다 — `sed` 앵커(2회 사고 → `AGENTS.md §4`), Boot 4 자동설정
침묵(→ `§3` 음성 케이스), DTO 이름 충돌(→ `§8`). **승격 경로는 작동하는데 입구가 없다.**

⚠️ **자동 추출하지 않는다.** 검증 관문 없는 자동 기록은 낡은 정보를 더 빨리 쌓는다.

### ⑤ 증거를 완료 관문으로

| | |
|---|---|
| 산출물 | `checks/verify.mjs` · `checks/regression-cases/` · `templates/skills/verify-tests/` · `templates/skills/close-task/` |
| ICFR 근거 | ⭐ `junit-verify` 스킬 · `specCoverage` 107/107 · `openapiSnapshot`+`pre-push` · `spec-dirty`/`spec-snapshot` L1·L2 분리 |
| 검증 상태 | **가장 검증된 축** · 스택 중립화 **설계안** |

⛔ **`BUILD SUCCESSFUL` 로 통과를 주장하지 않는다.** 테스트 0개여도 성공한다. `verify.mjs` 는 프로젝트가
선언한 검사를 돌린 뒤 **결과 파일을 읽어** 판정한다.

`close-task` 스킬 — 태스크 경계 게이트. 승인된 결정 2번(보안 상시 훅 제거)이 여기에 편입된다:

```
verify.mjs 전량 → 증거 요약 → 커밋 → /security-review 1회 → state/current.md 갱신
```

| | |
|---|---|
| 산출물 | `tools/trace-read.mjs` |
| 검증 상태 | **설계안** |

⛔⛔ **여기서 아티클을 따르지 않는다.** 아티클은 `runs/traces.jsonl` 을 새로 쓰라고 하지만,
`context-graph` 가 같은 자리에서 반대 결론에 도달했다:

⇒ **트레이스를 새로 쓰지 않는다.** `~/.claude/projects/<슬러그>/*.jsonl` 에 이미 전부 있다.
`trace-read.mjs` 가 거기서 run 을 복원하고, 사람은 **실패 원인 분류만** `state/lessons.md` 에 적는다.

## 6. 설계 원칙

계승 (`context-graph`):

| 원칙 | 왜 |
|---|---|
| 자동 로드되는 층을 늘리지 않는다 | 쌓일수록 매 세션 비용 |
| 값이 아니라 명령을 적는다 | 재생성되는 값은 낡는다 |
| 검증 안 된 것을 적지 않는다 | 틀린 기억은 없는 기억보다 나쁘다 |
| 저장소를 하나로 | 둘이면 반드시 어긋난다 |
| 자동 추출하지 않는다 | 검증 관문이 없다 |
| 의존성 0 | Node 내장만 |

신규:

| 원칙 | 왜 |
|---|---|
| **모든 산출물에 `검증됨`/`설계안` 딱지** | 6역할 전부를 만들기로 한 이상, 검증 여부를 숨기지 않는 것이 유일한 방어선 |
| **검사는 드물게 울려야 신호다** | 늘 exit 1 이면 사람이 무시한다 |
| **게이트는 correctness 에만 건다** | `referenceAudit` 을 `pre-push` 에 안 넣은 ICFR 의 판단을 따른다 |

## 7. 검증 — ⛔ 자기 보고도 도구 출력도 믿지 않는다

`SETUP.md` 가 설치 후 강제할 것:

1. **도구가 도는가** — 각 `tools/*.mjs` 를 실제 대상에서 1회씩, `git status --porcelain` 로 의도한 것만 바뀌었는지
2. **새 세션이 실제로 쓰는가** — `claude -p --model haiku` 도구 금지, §2 의 양성/음성 대조
3. **`/clear` 직후에도 로드되는가** — §2 의 미해결 의문. 여기서 재현을 시도한다
4. **`AGENTS.md` diff 를 사용자에게 보여준다** — 기존 내용 보존은 사용자만 판정한다

⛔ **눈으로 출력을 보고 「됐다」고 판단하지 않는다.** `context-graph` 는 그 방식으로 세 번 틀렸다.
