| 계획 형식 · 진행 체크박스 | ✅ superpowers `writing-plans` | ⛔ 고유값 아님 |

| **「완료」의 결정론적 증거** | ❌ 종료코드도 러너 요약도 테스트 0개를 통과시킨다 | ⭐ 고유값 |
| **묻지 않고 진행한 가정의 적립** | ❌ | ⭐ 고유값 |
| **반복 실패 → 규약 승격** | ❌ | ⭐ 고유값 |
| **상태 대장이 거짓말하는지 (해시)** | ❌ | ⭐ 대장이 있는 대상만 |

⭐ **실측 (Node 24.18):** `node --test` 는 `test()` 가 하나도 없는 파일을 `tests 1 · pass 1` 로 세고 exit 0 을 낸다.
junit 출력에는 그 파일이 통과한 `<testcase>` 로 들어간다. 종료코드도, 러너 요약도, 결과 XML 의 개수도 믿을 수 없다.

⛔ **이 표가 흐려지면 이 레포는 superpowers·git·CI 의 열등한 사본이다.** 도구를 추가할 때마다 줄을 넣고,
「이미 되나」가 ✅ 면 넣지 않는다.

## 4. 흐름

```
brainstorming ─(사람 승인)→ writing-plans ─(사람 승인)→ 실행 (subagent-driven 또는 executing-plans · TDD)
   ├ 실행 중 — 묻지 않는다: 가정은 decisions 에, 반복 실패는 lessons 에
   └ 완료를 주장하기 전 — node .harness/tools/verify.mjs   (verification-before-completion 이 돌릴 명령)
→ 계획의 마지막 태스크 = final-gate → finishing-a-development-branch

final-gate: verify → /ponytail-review(브랜치 diff) → 걷어낸 뒤 verify 재실행 → /security-review 1회 → 상태·교훈 갱신
```

- 설계·계획 승인은 superpowers 그대로 사람이 한다. **「멈추지 않는다」는 승인된 계획을 실행하는 동안에만** 적용한다
- final-gate 가 잊히지 않도록 규칙 파일이 「계획의 마지막 태스크는 final-gate」를 강제한다 — 관문이 체크박스가 된다
- ponytail 은 설치하되 `PONYTAIL_DEFAULT_MODE=off` 로 끈다. superpowers 의 설계·질문 단계와 ponytail 상시 모드(「설명 금지」)가 충돌하기 때문이다

## 6. 설치 — 대상에 놓이는 것

```
<대상>/
├── .harness/
│   ├── harness.json        ⭐ 경로 설정 — 모든 도구가 이것만 읽는다 (경로는 대상 루트 기준)
│   ├── lib/  tools/        도구 — Node 내장만
├── .claude/
│   ├── rules/harness.md    규칙 — CLAUDE.md·AGENTS.md 유무와 무관하게 로드
│   ├── skills/final-gate/  마지막 관문
│   ├── settings.json       권한 · env · 플러그인 선언 — 기존 키 보존 병합
│   └── settings.local.json 같은 플러그인이 다른 마켓으로 이미 켜져 있을 때만
└── docs/harness/{decisions,lessons}.md   대상이 이미 쓰는 파일이 있으면 그 경로를 harness.json 에 적는다
```

- **도구를 `.harness/` 아래에 둔다.** 대상 루트의 `lib/` · `tools/` 는 흔한 이름이라 기존 코드와 부딪힌다
- **플러그인** — `policy-apply` 가 `enabledPlugins`(`superpowers@claude-plugins-official` · `ponytail@ponytail`) ·
  `extraKnownMarketplaces`(ponytail) · `env.PONYTAIL_DEFAULT_MODE=off` 를 선언한다. 프로젝트에만 선언된 플러그인은
  팀원 PC 에 자동 설치되지 않으므로(공식 문서) 규칙 파일에 설치 명령을 남긴다. 이미 사용자 범위로 설치된 PC 에서는
  그 프로젝트에서 세션을 열 때 프로젝트 범위 설치 기록이 자동으로 생긴다(실측)
- **중복** — 같은 이름의 플러그인을 두 마켓에서 켰을 때 무엇이 로드되는지는 문서에 없다. 설치하는 사람의 PC 에 다른
  마켓의 superpowers·ponytail 이 이미 켜져 있으면 설치하지 않고, `.claude/settings.local.json` 에서 프로젝트 쪽 id 를
  `false` 로 끈다 (우선순위 local > project > user)
- **신규 vs 기존** — git 이력이 있으면 교훈을 2~3건 소급 입력한다. 없으면 건너뛴다. 대장(STATE)은 대상이 이미 쓰는 경우에만 잇는다

## 7. 설계 원칙

| 원칙 | 왜 |
|---|---|
| 자동 로드되는 층은 규칙 파일 하나만 더한다 | 쌓일수록 매 세션 비용. 플러그인 층은 결정(§0)으로 수용한 것이다 |
| 값이 아니라 명령을 적는다 | 재생성되는 값은 낡는다 |
| 검증 안 된 것을 적지 않는다 | 틀린 기억은 없는 기억보다 나쁘다 |
| 저장소를 하나로 | 교훈 장부는 lessons 하나 — 두 번째 장부(예: graphify `reflect`)를 두지 않는다 |
| 자동 추출하지 않는다 | 검증 관문이 없다 |
| 의존성 0 | Node 20+ 내장만 |
| 검사는 드물게 울려야 신호다 | 늘 exit 1 이면 사람이 무시한다 |
| 게이트는 correctness 에만 건다 | 진행도로 막으면 급한 수정이 막힌다 |
| 자동 승인(allow)에는 인자로 쓰기·실행에 닿지 않는 명령만 둔다 | allow 는 사람의 확인을 건너뛴다 — `find -exec` · `sort -o` · `git diff --output` · `node .harness/tools/*` 의 `../` 는 거부 목록을 우회한다 (10-02 보안 리뷰) |
| 대상의 기존 파일을 옮기거나 덮어쓰지 않는다 | 규칙은 새 파일, 설정은 병합, 상태는 기존 경로를 그대로 적는다 |
| 특정 프로젝트 이름을 넣지 않는다 | 범용 템플릿이다 |
| OS 를 가리지 않는다 | 셸은 플랫폼 기본(`sh`/`cmd`), 경로는 `node:path`, 줄바꿈은 `\r?\n` |

## 8. 검증 — ⛔ 자기 보고도 도구 출력도 믿지 않는다

`SETUP.md` 가 설치 후 강제할 것:

1. **도구가 도는가** — 각 도구를 대상에서 1회씩, `git status --porcelain` 으로 의도한 것만 바뀌었는지
2. **규칙이 로드되는가** — `claude -p` 도구 금지, 규칙 파일에만 있는 사실(양성)과 어디에도 없는 사실(음성) 대조
3. **ponytail 이 꺼졌는가** — 새 세션에 ponytail 규칙이 주입되지 않는지
4. **플러그인이 하나씩인가** — `claude plugin list --json` 에서 superpowers·ponytail 이 각각 하나만 켜졌는지

⚠️ **알려진 위험** — ponytail 의 모드 플래그는 사용자 전역 파일이다. 다른 프로젝트 세션이 동시에 켜져 있으면
꺼 둔 프로젝트에도 규칙이 새어 들어올 수 있다. 재현되면 lessons 에 적는다.

## 9. ⛔ 도입하지 말아야 할 때

| 이럴 땐 하지 않는다 | 왜 |
|---|---|
| 결정론적 검사를 만들 수 없는 스택이다 | verify 가 비면 나머지가 장부질에 그친다 |
| 계획 없이 한두 번 묻고 끝나는 작업뿐이다 | 가정·교훈이 쌓일 반복이 없다 |
| 프로젝트 수명이 몇 주다 | LESSONS 는 반복이 있어야 승격된다 |
| superpowers 를 쓰지 않기로 한 팀이다 | 흐름의 베이스가 superpowers 다 |

## 10. 범위 밖

- **graphify** — 큰 레거시 코드베이스에 한해 선택 적용. 기본 설치 제외. 쓸 때의 규칙:
  `--code-only` (tree-sitter AST, LLM 없음) · 안내 문구는 `CLAUDE.md` 대신 `.claude/rules/` 에 둔다
  (`CLAUDE.md` 가 새로 생기면 `AGENTS.md` 로드가 꺼진다) · `graphify reflect` 를 쓰지 않는다 (교훈 장부는 lessons 하나) ·
  Python 3.10+ 가 필요하다
- **도메인 지식 그래프** — 「현업 용어 → 코드 식별자」는 별도 지식 레이어의 일이다
